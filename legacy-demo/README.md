# legacy-demo: тренажёр по работе с чужим кодом

Учебный проект модуля 7 курса «ИИ для разработчиков».

В папке `legacy/` лежит намеренно плохо написанный, но полностью рабочий
JavaScript. В папке `after/` лежит он же, перенесённый на TypeScript.
Задача практикума: не переписать исходник с нуля, а мигрировать его безопасно,
шаг за шагом, ни разу не потеряв поведение.

## Что делает программа

`legacy/report.js` читает файл заказов интернет-магазина `data/orders.csv`
и строит по нему отчёт:

* выручка по категориям товаров: сумма, скидки, налог, итог, доля;
* выручка по месяцам;
* пять товаров с наибольшим оборотом;
* сколько раз применялся каждый код скидки;
* количество и сумма возвратов.

Результаты складываются в папку `out/`:

| Файл | Что внутри |
|---|---|
| `out/report.txt` | текстовый отчёт, он же печатается в консоль |
| `out/revenue.csv` | выгрузка сумм в разрезе «категория и месяц» |

## Правила расчёта

1. Сумма строки равна количеству, умноженному на цену.
2. Код скидки даёт процент: `SALE5` пять процентов, `SALE10` десять,
   `SALE15` пятнадцать, `VIP20` двадцать. Незнакомый код скидки не даёт.
3. Заказ дороже 1 000 получает дополнительно пять процентов скидки.
4. Общая скидка не может превышать 25 процентов.
5. Налог 20 процентов начисляется на сумму после скидки.
6. Строка со статусом `C` (отменён) в выручку не попадает.
7. Строка со статусом `R` (возврат) уменьшает выручку и скидки не получает.
8. Строки с нечисловым количеством или ценой пропускаются с предупреждением.
9. Дата в чужом формате ошибкой не считается: заказ попадает в группу `0000-00`.

## Как запустить

Нужен только Node.js версии 22.12 или новее. Проверить: `node --version`.

### Windows, PowerShell

```powershell
cd C:\курс\legacy-demo
npm ci
npm run legacy
```

### macOS, Terminal

```bash
cd ~/курс/legacy-demo
npm ci
npm run legacy
```

Ожидаемый вывод начинается с трёх предупреждений и продолжается отчётом:

## Команды

| Команда | Что делает |
|---|---|
| `npm run legacy` | запускает исходную версию |
| `npm run typecheck` | проверяет типы, ничего не собирая |
| `npm run build` | собирает TypeScript в `after/dist` |
| `npm run after` | собирает и запускает новую версию |
| `npm run test:characterization` | 20 тестов исходной версии |
| `npm run test:after` | 71 тест новой версии, включая эквивалентность |
| `npm test` | все 91 тест |
| `npm run compare` | сверяет вывод двух версий |

## Тесты

Характеризующие тесты в `tests/characterization/` не проверяют, что программа
работает правильно. Они фиксируют, как она работает сегодня, включая известную
ошибку округления. Пока они зелёные, менять код безопасно.

Тесты в `after/tests/` устроены иначе: там по файлу на модуль, и они проверяют
уже правильное поведение. Отдельный файл `equivalence.test.ts` запускает обе
версии и сравнивает их результаты.

## Сверка двух версий

```
npm run compare
```

Скрипт печатает два блока. Первый доказывает, что новая версия в режиме
совместимости повторяет отчёт исходной символ в символ. Второй показывает
единственное запланированное отличие: исправленное округление скидки.

## Что изменилось в поведении после миграции

Ровно одно: скидка теперь округляется до копеек по правилу «половина вверх»,
а не отбрасывается. На штатном файле заказов сумма всех скидок меняется
с 1 404,22 на 1 404,72. Все прочие числа, счётчики, порядок строк и формат
отчёта остались прежними, и это проверяется тестом.

Флаг `--legacy-rounding` возвращает прежний, неверный расчёт:

```
node after/dist/main.js --legacy-rounding
```

Есть и второе отличие, невидимое на этих данных, но объявленное отдельно:
новый разбор чисел строгий. `Number.parseFloat("12abc")` возвращает 12,
а `parseMoneyToCents("12abc")` возвращает `null`, и строка отбраковывается.
На `data/orders.csv` таких значений нет, поэтому отчёт не меняется.

## Важное предупреждение

Код в `legacy/report.js` написан плохо намеренно. В нём есть и стилевые
проблемы, и одна настоящая ошибка в расчёте. Искать их самостоятельно и есть
задание практикума, поэтому список проблем здесь не приводится.

Не начинайте с переписывания. Порядок работы описан в раздатке
«Модуль 7. Работа с legacy-кодом».
