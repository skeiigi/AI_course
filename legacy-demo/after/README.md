# after: результат миграции на TypeScript

Тот же отчёт, что и в `legacy/report.js`, но разложенный по слоям и с типами.
Поведение сохранено полностью, кроме одной осознанно исправленной ошибки.

## Слои

| Модуль | Ответственность | Чего в нём нет |
|---|---|---|
| `src/config.ts` | константы бизнес-правил и настройки запуска | расчётов |
| `src/types.ts` | типы данных между слоями | логики |
| `src/money.ts` | разбор, округление и печать денег | бизнес-правил |
| `src/loader.ts` | чтение CSV, разбор строк, причины отказа | денег и формата отчёта |
| `src/pricing.ts` | расчёт сумм по одной строке заказа | файлов и печати |
| `src/aggregate.ts` | суммы по группам, топ товаров, строки выгрузки | форматирования |
| `src/render.ts` | текст отчёта и текст выгрузки | расчётов |
| `src/main.ts` | разбор аргументов и склейка слоёв | бизнес-логики |

Границы проверяются глазами по импортам: `pricing` не импортирует `node:fs`,
`render` не импортирует `pricing`, `loader` не знает про отчёт.

## Что изменилось по сравнению с исходной версией

| Было в `legacy/report.js` | Стало в `after/src` |
|---|---|
| одна функция на 180 строк | восемь модулей, самая длинная функция 70 строк |
| десять глобальных накопителей | значения передаются аргументами и возвращаются |
| `var` и `let` вперемешку | `const` по умолчанию |
| данные ездят массивами `l[3]`, `v[4]` | именованные поля с типами |
| одна и та же формула в трёх местах | одна функция `calculateLine` |
| деньги в `number` с дробной частью | деньги в целых копейках |
| магические числа 1000, 5, 25, 0.2 | именованные константы в `config.ts` |
| `console.log` внутри расчёта | расчёт возвращает значения, печатает `main.ts` |
| плохая строка молча пропускается | `RowOutcome`, который нельзя не проверить |

## Деньги хранятся в копейках

Это главное правило модуля `money.ts`. Дробный `number` для денег не годится:
`0.1 + 0.2` в нём не равно `0.3`, и на длинных суммах ошибка накапливается.
Целые копейки не накапливают ничего. Округление делается один раз и явно,
функцией `divideRoundHalfUp`.

## Что изменилось в поведении

Ровно одно: скидка округляется до копеек по правилу «половина вверх», а не
отбрасывается. Исходная версия считала скидку в плавающей точке и теряла
третий знак, из-за чего сумма скидок занижалась на копейки.

На штатном файле заказов сумма всех скидок меняется с 1 404,22 на 1 404,72.
Все прочие числа, счётчики, порядок строк и формат отчёта остались прежними.

## Режим совместимости

Флаг `--legacy-rounding` возвращает прежний, неверный расчёт скидки.
Он нужен только для доказательства эквивалентности миграции:

```
node after/dist/main.js --legacy-rounding
```

В этом режиме отчёт совпадает с эталоном
`tests/characterization/golden/report.txt` символ в символ. Проверяется тестом
`after/tests/equivalence.test.ts`.

## Запуск

Из папки проекта `legacy-demo`:

```
npm run build
node after/dist/main.js
node after/dist/main.js --orders data/orders.csv --out-dir out-new
node after/dist/main.js --quiet
```

## Тесты

```
npm run test:after
```

Обратите внимание на `after/tests/pricing.test.ts`, тест «скидка округляется
по правилу «половина вверх»». Это тот же случай, который в
`tests/characterization/legacy.test.ts` зафиксирован с прежним, неверным
значением. Ожидание изменено вместе с исправлением расчёта, а не подогнано
под новый код.
