# AGENTS.md

Файл памяти для ИИ-агента, который работает с этим репозиторием.
Прочитай его целиком перед первой правкой кода.

## 1. Что за проект

Сервис бронирования тайм-слотов по типу Calendly. Организатор заводит виды
активности и расписания, гость выбирает свободный слот и оставляет бронь.

Это запасной вариант эталонного проекта курса «ИИ для разработчиков»
(СФУ, Академия Softline) для групп, которые работают на Python. Его читают
студенты четвёртого курса направления «Web-программирование и разработка ПО».
Они уверенно владеют git, C#, ASP.NET Core, SQL, HTML, CSS, JavaScript,
React и Angular. Они впервые видят Docker, непрерывную интеграцию,
автоматические тесты, TypeSpec, агентов и MCP.

Отсюда главный критерий качества: код должен быть современным и честным,
но при этом читаться с первого раза на занятии. Не примитивным и не изощрённым.

## 2. Стек

| Слой | Технология |
|---|---|
| Язык | Python 3.11 и выше, целевая версия 3.12 |
| Веб-фреймворк | FastAPI |
| Проверка данных | Pydantic v2 |
| База данных | SQLite через SQLAlchemy 2.x |
| Контракт API | TypeSpec, из него собирается OpenAPI 3.1 |
| Интерфейс | HTML, CSS и JavaScript без сборки, отдаётся тем же FastAPI |
| Тесты | pytest, запросы через `TestClient` и httpx |
| Линтер и форматирование | ruff |
| Контейнер | Docker, docker compose |
| Непрерывная интеграция | GitHub Actions |

Зависимости перечислены в `requirements.txt` с точными версиями и ставятся
одной командой в виртуальное окружение. Node.js нужен только для пересборки
контракта: собранный `contract/openapi.yaml` лежит в репозитории, поэтому
для запуска сервиса и тестов достаточно Python.

## 4. Как запускать

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python seed.py
uvicorn app.main:app --reload
```

macOS и Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python seed.py
uvicorn app.main:app --reload
```

Интерфейс: http://127.0.0.1:8000
Документация API: http://127.0.0.1:8000/docs
Схема, которую отдаёт код: http://127.0.0.1:8000/openapi.json

В контейнере, один порт и отдельный том под базу:

```bash
docker compose up -d --build
```

Остановить: `docker compose down`, удалить вместе с бронями:
`docker compose down -v`.

## 5. Как тестировать

```bash
pytest -q
ruff check .
ruff format --check .
```

Все проверки обязаны проходить перед любым коммитом. Сейчас в проекте 91 тест:
модульные на движок слотов и на модели, интеграционные на все эндпоинты,
проверки кодов и текстов ошибок и тест соответствия контракту.

Те же три команды выполняет непрерывная интеграция,
файл `.github/workflows/ci.yml`.

Пересборка контракта нужна только при правке `main.tsp` и требует Node.js:

```bash
cd contract
npm install
npx tsp compile .
```

## 6. Порядок работы Design First

Изменения вносятся строго в этом порядке:

1. Правим `contract/main.tsp`.
2. Пересобираем контракт: `npx tsp compile .` в папке `contract`.
3. Приводим схемы Pydantic в `app/schemas.py` в соответствие с контрактом.
4. Правим роутеры в `app/routers/`, при необходимости таблицы
   в `app/models.py` и коды ошибок в `app/errors.py`.
5. Правим интерфейс в `app/static/app.js`, если изменились ответы сервиса.
6. Запускаем `pytest -q`.

Тесты в `tests/test_contract.py` читают `contract/openapi.yaml` и требуют,
чтобы приложение ему подчинялось: пути, методы, наборы полей моделей,
обязательные поля и имена query-параметров сверяются со схемой, которую FastAPI
отдаёт по `/openapi.json`. Если начать с кода, эти тесты упадут. Так и задумано.

Коммитить `contract/openapi.yaml` обязательно: именно этот файл читают тесты,
и по нему контракт можно прочитать и отдать другой команде, не запуская сборку.

## 7. Соглашения по коду

- Комментарии и тексты для пользователя на русском языке. Имена переменных,
  функций и файлов на английском.
- Комментарий объясняет решение. «Здесь увеличиваем счётчик» не нужно,
  «счётчик нужен, чтобы после брони перечитать сетку» нужно.
- Имена говорящие: `build_slots`, `find_slot`, `weekdays_from_text`.
  Не `process`, не `handle`, не `data2`.
- Поля API в стиле `snake_case`: `duration_minutes`, `start_time`,
  `guest_email`. Так они названы в контракте, и в Python так же называются
  переменные, поэтому второго словаря держать не нужно.
- Даты это строки «ГГГГ-ММ-ДД», время это строки «ЧЧ:ММ:СС»: в таком виде они
  описаны в контракте и приняты в схемах Pydantic. Объекты `date` и `time`
  живут внутри расчётов и базы, преобразования собраны в `app/schemas.py`.
  Момент создания брони хранится в UTC, смотри `now_utc` в `app/models.py`.
- Бизнес-логика вычисления слотов живёт в `app/slot_engine.py`
  и не ходит в базу. Роутер достаёт данные и передаёт их в чистые функции.
- Проверка входных данных делается схемами Pydantic: тело запроса приходит
  готовой моделью, параметры запроса проверяются в объявлении обработчика.
  Ручных проверок формата в обработчиках не пишем, описание данных и так живёт
  в двух видах, в TypeSpec и в схемах Pydantic. Ошибку
  `RequestValidationError` превращает в ответ 422 общий обработчик
  в `app/main.py`.
- Ошибки API это `ApiError` с кодом состояния, машиночитаемым кодом и текстом
  на русском. Тело ответа при любой ошибке одинаковое: `{code, message}`.
  Коды и тексты собраны в `app/errors.py`, чтобы одна ситуация всегда
  описывалась одинаково. Коды предметной области продублированы в союзе
  `ErrorCode` в контракте, служебные `route_not_found` и `internal_error`
  живут только в коде.
- Роутеры объявляются обычным `def`. Асинхронные обработчики здесь не нужны:
  обращения к SQLite синхронные, FastAPI выполняет такие функции в пуле потоков.
- Аннотации типов обязательны у функций. Никаких метаклассов, дескрипторов,
  декораторов собственного изготовления и прочих продвинутых приёмов.
- Функция помещается на экран. Если не помещается, её надо разделить.
- Длина строки до 100 символов, порядок импортов задаёт ruff.
- Русская типографика: длинных тире не используем, кавычки «ёлочки».

## 8. Чего делать нельзя

- Не добавлять зависимости без явной необходимости. Каждая новая строка
  в `requirements.txt` это лишний шаг установки для студента на своём ноутбуке.
- Не переводить интерфейс на React, Vue, TypeScript или любой сборщик.
  Не подключать Tailwind, готовые наборы компонентов и библиотеки иконок.
  Интерфейс написан на собственном CSS намеренно: студенты должны видеть,
  как он устроен. Отдаёт его тот же FastAPI.
- Не менять SQLite на PostgreSQL. Причина в `docs/adr/0001-vybor-sqlite.md`.
- Не хранить слоты в базе. Причина в `docs/adr/0002-generatsiya-slotov-na-letu.md`.
- Не убирать частичный индекс `uq_active_booking` и не заменять оба рубежа
  защиты одним. Причина в `docs/adr/0003-zashchita-ot-dvoynogo-bronirovaniya.md`.
- Не править `contract/openapi.yaml` руками. Этот файл собирается компилятором
  из `contract/main.tsp`.
- Не добавлять Alembic и миграции: в проекте их нет намеренно.
- Не делать роутеры асинхронными и не тащить асинхронный драйвер базы.
- Не ставить нестрогие ограничения версий (`>=`, `~=`) в `requirements.txt`.
  Версии зафиксированы точно, чтобы через полгода ставилось то же самое.
- Не коммитить `booking.db`, `.venv/`, `__pycache__/`
  и `contract/node_modules/`.
- Не использовать длинные тире в русских текстах и комментариях.
- Не писать «умный» короткий код ценой понятности.

## 9. Частые задачи

**Добавить поле в модель.** Правим `contract/main.tsp`, пересобираем контракт,
правим схему в `app/schemas.py`, добавляем столбец в таблицу `app/models.py`,
удаляем `booking.db` (миграций в проекте нет), при необходимости правим
`app/static/app.js`, добавляем тест, запускаем `pytest -q`.

**Добавить эндпоинт.** Описываем операцию в `contract/main.tsp`, пересобираем
контракт, создаём или дополняем роутер в `app/routers/`, подключаем его
в `app/main.py`, добавляем тесты. Тест соответствия контракту сам проверит,
что набор путей и методов совпадает со списком операций.

**Поменять правило генерации слотов.** Правим только `app/slot_engine.py`
и тесты в `tests/test_slot_engine.py`. Роутеры трогать не нужно.

**Добавить новый код ошибки.** Добавляем значение в союз `ErrorCode`
в `contract/main.tsp`, пересобираем контракт, добавляем его в `ErrorCode`
и функцию-заготовку в `app/errors.py`, бросаем эту ошибку в роутере,
добавляем проверку в `tests/test_errors.py`.
