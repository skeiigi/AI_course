# after: результат рефакторинга

Тот же отчёт, что и в `legacy_report.py`, но разложенный по слоям и с типами.
Поведение сохранено полностью, кроме одной осознанно исправленной ошибки.

## Слои

| Модуль | Ответственность | Чего в нём нет |
|---|---|---|
| `orders_report/config.py` | константы бизнес-правил и настройки запуска | расчётов |
| `orders_report/models.py` | типы данных между слоями | логики |
| `orders_report/money.py` | разбор, округление и печать денег | бизнес-правил |
| `orders_report/loader.py` | чтение CSV, разбор строк, причины отказа | денег и формата отчёта |
| `orders_report/pricing.py` | расчёт сумм по одной строке заказа | файлов и печати |
| `orders_report/aggregate.py` | суммы по группам, топ товаров, строки выгрузки | форматирования |
| `orders_report/reporting.py` | текст отчёта, текст выгрузки, запись файлов | расчётов |
| `main.py` | разбор аргументов и склейка слоёв | бизнес-логики |

Границы проверяются глазами по импортам: `pricing` не импортирует `pathlib`,
`reporting` не импортирует `pricing`, `loader` не знает про отчёт. Последнее
проверяется и тестом `test_reporting_does_not_import_pricing`.

## Что изменилось по сравнению с исходной версией

| Было в `legacy_report.py` | Стало в `after/orders_report` |
|---|---|
| одна функция на 180 строк | семь модулей, самая длинная функция 70 строк |
| десять глобальных накопителей через `global` | значения передаются аргументами и возвращаются |
| данные ездят списками `l[3]`, `v[4]` | датаклассы с именованными полями |
| одна и та же формула в трёх местах | одна функция `pricing.calculate` |
| деньги в `float` | деньги в `Decimal` |
| магические числа 1000, 5, 25, 0.2 | именованные константы в `config.py` |
| `print` внутри расчёта | расчёт возвращает значения, печатает `main.py` |
| плохая строка молча пропускается | причина попадает в `LoadResult.skipped` |
| `int(float(x))` молча принимает `1.9` | `money.parse_integer_strict` отказывается |

## Деньги хранятся в Decimal

Это главное правило модуля `money.py`. Тип `float` для денег не годится:
`0.1 + 0.2` в нём не равно `0.3`, и на длинных суммах ошибка накапливается.
`Decimal` считает в десятичной системе и такой ошибки не даёт.

Округление делается один раз и явно, функцией `to_money`. Встроенный `round`
здесь не подходит: он округляет половину к чётному, поэтому `round(2.675, 2)`
даёт 2,67. Для денег нужна половина вверх, и её задаёт `ROUND_HALF_UP`.

Разбор чисел тоже живёт здесь и тоже строгий. Голый `Decimal` принимает
`NaN`, `Infinity` и запись `1e3` без ошибки. Одно значение `NaN`, попав
в накопитель, молча превращает в `NaN` весь отчёт, и заметить это почти
невозможно. Поэтому формат проверяется регулярным выражением до разбора.

## Что изменилось в поведении

Ровно одно: скидка округляется до копеек по правилу «половина вверх»,
прежняя версия дробную часть отбрасывала. Исходная версия считала скидку
в плавающей точке и теряла третий знак, из-за чего сумма скидок занижалась.

На штатном файле заказов сумма всех скидок меняется с 1 404,22 на 1 404,72.
Все прочие числа, счётчики, порядок строк и формат отчёта остались прежними.

Есть и второе отличие, невидимое на этих данных, но объявленное отдельно:
новый разбор чисел строгий. `int(float("1.9"))` в исходной версии возвращает 1,
а `money.parse_integer_strict("1.9")` возвращает `None`, и строка
отбраковывается. В `orders.csv` таких значений нет, поэтому отчёт не меняется.

## Режим совместимости

Флаг `--legacy-rounding` возвращает прежний, неверный расчёт скидки.
Он нужен только для доказательства эквивалентности рефакторинга:

```
python after/main.py --legacy-rounding
```

В этом режиме отчёт совпадает с эталоном `tests/golden/report.txt` символ
в символ. Проверяется тестом `after/tests/test_equivalence.py`, который
запускает обе версии по-настоящему, а не сравнивает с записанным файлом.

## Запуск

Из папки проекта `legacy-demo-python`:

```
python after/main.py
python after/main.py --out-dir out-new
python after/main.py --quiet
```

## Тесты

```
python -m pytest after -q
```

Ожидается `141 passed`.

|---|---|---|
| `test_money.py` | округление, разбор чисел, печать | 58 |
| `test_loader.py` | чтение CSV и причины отказа | 26 |
| `test_pricing.py` | правила скидок и налога | 9 |
| `test_aggregate.py` | суммы по группам, топ, выгрузка | 12 |

| `test_equivalence.py` | обе версии дают один результат | 15 |

Обратите внимание на `after/tests/test_pricing.py::test_discount_is_rounded_half_up`.
Это тот же случай, который в `tests/test_characterization.py` зафиксирован
с прежним, неверным значением. Ожидание изменено вместе с исправлением
расчёта, а не подогнано под новый код.
