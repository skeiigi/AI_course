# ADR 0006. Сообщения по секрету брони

- **Статус:** принято
- **Дата:** 7 октября 2026

## Решение

Сообщения хранятся в SQLite в таблице `booking_messages` с внешним ключом на
бронь. Чтение и запись проходят через те же ID и Bearer-секрет, что просмотр
брони. Проверка секрета выполняется перед любым запросом к сообщениям; при
неверном секрете API возвращает 404. Ответы не кэшируются браузером.

Поле `sender_name` задаёт сам отправитель. Сервер не приписывает сообщению
проверенную роль гостя или организатора, поскольку общая ссылка не позволяет
их различить. Публикация сообщений вне этой страницы и индексация не нужны.

Новые сообщения разрешены лишь до начала активной встречи. Правило проверяет
сервер с единым часовым поясом `Asia/Krasnoyarsk`. После отмены или начала
встречи API возвращает конфликт 409. Для обновления клиент опрашивает API с
интервалом, без дополнительной инфраструктуры WebSocket.
